# Восстановление пароля по статику — 24 часа

1. В Supabase → SQL Editor выполните `password_recovery_migration.sql` (создаёт таблицу заявок, не удаляя пользователей).
2. В Supabase → Edge Functions создайте или обновите функцию с **точным именем** `password-recovery` и вставьте содержимое `supabase/functions/password-recovery/index.ts`.
3. В Supabase → Edge Functions → Secrets добавьте `RESET_CODE_SECRET`: длинную случайную строку минимум 32 символа. Не публикуйте её на Netlify. Убедитесь, что доступны `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_ANON_KEY`.
4. Для этой функции отключите проверку **Verify JWT** на уровне шлюза: запрос заявки и применение кода идут без входа. Функция сама проверяет JWT и роль `admin` для просмотра заявок и генерации кодов. Другие функции не меняйте.
5. Загрузите файлы сайта на Netlify и обновите страницу с очисткой кеша.
6. Пользователь → «Забыли пароль?» → вводит статик → «Отправить заявку». Администратор → «Администрирование» → «Сгенерировать код» → передаёт 8 цифр пользователю. Пользователь вводит код и новый пароль дважды. Код действует 24 часа с момента генерации и одноразовый; после 5 неверных попыток требуется новый код.

**Важное ограничение:** проверка попыток и обновление пароля в этой версии выполняются несколькими запросами, а не одной атомарной транзакцией. Для строгой защиты от одновременных запросов и злоупотребления публичным endpoint потребуется серверный rate limit и атомарная RPC-процедура. До публичного запуска рекомендуется включить защиту от ботов/ограничение запросов на уровне инфраструктуры. Пароль обновляется через Supabase Admin API, а не в таблице профилей.
