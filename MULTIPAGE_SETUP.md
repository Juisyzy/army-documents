# Многостраничные приказы А4

1. Сохраните резервную копию репозитория и базы.
2. В Supabase → SQL Editor выполните MULTIPAGE_MIGRATION.sql. Проверьте отсутствие ошибок.
3. Загрузите в корень GitHub Pages только index.html, app.js, extra.css, pagination.js. SQL и инструкцию в публичный репозиторий загружать необязательно.
4. Дождитесь публикации, откройте сайт с Ctrl+F5.
5. Сначала проверьте в конструкторе длинный текст на 2–3 листа в каждом подразделении. Убедитесь, что подпись и печать стоят на последнем листе и страницы не перекрываются.
6. Опубликуйте тестовый приказ. Проверьте, что каждая страница скачивается как отдельный PNG и открывается в реестре. Затем проверьте старый одностраничный приказ.

Изменения базы: добавляется только таблица order_pages и политики доступа; старые записи не изменяются. Первая страница по-прежнему хранится в orders.image_path. Остальные страницы сохраняются в order_pages.

Ограничения: система разбивает текст по словам, а не по абзацам; длинные слова и сложные вставки следует проверить визуально. Доступность дополнительной загрузки зависит от действующих политик Storage. Если Supabase вернёт ошибку, сохраните её текст и не повторяйте публикацию вслепую (номер может быть зарезервирован).
